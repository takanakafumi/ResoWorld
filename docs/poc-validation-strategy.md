# ResoWorld PoC検証戦略

## 1. 目的

PoCで検証する中心命題は次のとおりである。

> 過去の探索記録から根拠付きの知識接続を立ち上げると、本人も明確には意識していなかった見方が生まれ、次の探索につながるか。

Entity抽出そのものや、見栄えのよいグラフ・地図を作ることは、PoCの成功条件ではない。

## 2. 検証対象

最初のシナリオは「宗像 → 宇佐 → 国東」とする。

対象文書：

- `旅行記/宗像探索.txt`
- `旅行記/北東九州・宇佐への旅 1日目.txt`
- `旅行記/国東・宇佐の旅 ― 2日目.txt`

これらは非公開のローカルデータとして扱う。

このシナリオを選ぶ理由は、海上交通、祭祀、国家、八幡信仰、神仏習合、山岳信仰、修験、地域社会という複数の観点を、場所と時代をまたいで比較できるためである。

## 3. 検証上の注意

現在の旅行記は、純粋なフィールドノートだけではない。以下が一つの文章内に混在している。

- 現地で本人が観察したこと
- 本人の感想、疑問、仮説
- AIによる整理、解釈、提案
- 外部資料から補足された歴史的説明
- 伝承、異説、未検証の関連候補

したがって、AIが文章から抽出した関係を直接「事実」として登録してはならない。すべての接続はClaimとして保持し、原文、情報の性質、生成元、確認状態へ戻れるようにする。

## 4. 検証フェーズ

### Phase 0 — Gold Dataset

対象3文書から、人が重要と判断するClaimを30〜50件選ぶ。

各Claimには最低限、以下を付ける。

- 主体、関係、対象
- 根拠となる原文
- 元文書
- 情報の性質
- 対象時代
- 関係する場所
- 初期レビュー状態

Gold Datasetの目的は、完全な歴史データベースを作ることではない。抽出粒度、表示価値、ノイズの境界を決めることである。

### Phase 1 — AI抽出評価

同じ3文書をAIで構造化し、Gold Datasetと比較する。

評価観点：

- 重要な観察・疑問・関係を取りこぼしていないか
- AI自身の過去の発言を史実として扱っていないか
- 仮説や伝承を事実へ昇格させていないか
- 同じEntityの表記揺れを適切に統合できるか
- 異なる時代の関係を同時代の関係として混ぜていないか
- 原文からは直接言えない推論を区別しているか

### Phase 2 — Evidence Graph

原文、Claim、Entity、Relationを相互にたどれるレビュー画面を作る。

最低限必要な操作：

- 文書またはEntityからClaimを絞り込む
- Relationを選択して根拠となる原文を見る
- 情報の性質と対象時代を確認する
- `suggested` を `confirmed` または `rejected` に変更する
- 同一Entityの候補を統合または分離する

### Phase 3 — 文書横断の接続

確認済みClaimを使い、文書間の共通点、相違点、欠けている接続を生成する。

AIは答えを断定するのではなく、以下を提示する。

- 比較可能な共通テーマ
- 接続を支持するClaim
- 接続に反するClaimまたは不確実性
- 追加で必要な資料・観察
- 新しく生まれる問い

### Phase 4 — 空間と時間

Evidence Graphに小規模な2D地図と時代フィルターを加える。

次の時間を混同しない。

- `observed_at`: ユーザーが現地を訪問・観察した時点
- `documented_at`: 文書に記録した時点
- `historical_time`: Claimが対象とする歴史上の時点または期間

高精細な3D Atlasは、この段階で必要性が確認されてから実装する。

### Phase 5 — 次の探索

確認済みClaimと未解決の問いから、次の行動を提案する。

提案は少なくとも以下を説明する。

- どの問いを検証する提案か
- 現在の記録では何が不足しているか
- なぜその場所・資料・観察が有効か
- 現地探索、文献調査、再確認のどれか
- 提案を支えるClaim

## 5. PoCの画面仮説

最初の画面は、グラフだけで完結させない。

```text
┌────────────────┬────────────────────┐
│ Documents      │ Evidence Graph     │
│ 原文・該当箇所 │ Entity / Claim     │
│ ハイライト     │ / Relation         │
├────────────────┴────────────────────┤
│ Claim詳細：性質・時代・場所・根拠・確認状態 │
├─────────────────────────────────────┤
│ 小規模Map / 時代フィルター / 新しい問い      │
└─────────────────────────────────────┘
```

## 6. 成功条件

PoCの第一段階は、次をすべて満たした場合に成功とする。

1. Gold Datasetで重要としたClaimの80％程度を、大幅な手修正なしに抽出できる
2. 画面上のすべてのClaimとRelationから、根拠となる原文へ戻れる
3. 観察・史料・考古学・伝承・仮説・異説・AI提案を混同しない
4. 訪問時点、記録時点、歴史上の時代を混同しない
5. 既存の旅行記を個別に読むだけでは明確でなかった、有用な接続または問いが最低1件生まれる
6. その問いに対して、根拠を説明できる次の探索候補が最低1件生まれる

## 7. PoCではまだ検証しないこと

- 全国・全時代の網羅性
- 多人数利用
- ソーシャル機能
- 高精細な3D地形
- 完全自動の歴史解説
- 完全自動のEntity統合
- Graph DBの必要性
- ポイント、ランキング等のゲーム要素
