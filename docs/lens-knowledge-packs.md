# LENS基礎知識パック

> 新しい旅行記を追加した際に、既存LENSを使うか、Knowledge Packを更新するか、新規LENSを作るかの判断手順は[旅行記追加とLENS更新の運用手順](./adding-travel-journal-and-lens.md)を参照する。

## 目的

LENSは、固定画像でもAIが毎回自由に生成する図でもない。比較的静的な基礎知識と、ユーザーの探索記録、選択中の関心、派生分析を合成して描画する。

```text
基礎知識パック（版管理）
  ＋ ユーザーの探索記録（正本）
  ＋ 選択中の場所・関心
  ＋ Derived Synthesis（再生成可能）
  ↓
LensProjection
  ↓
地図・系譜図・関係図・タイムライン
```

## 基礎知識と表示プリセットを分離する

基礎知識はEntityとAssertionのグラフとして保持する。画面に見える木構造やルートは`LensPreset`による投影であり、正本そのものではない。

例として「アマテラス → 天忍穂耳尊 → 瓊瓊杵尊」という主線を表示しても、背後には配偶神、兄弟神、神話上の出来事、祭祀地、古事記と日本書紀の記述差を保持できる。

## LENS図とMAPをPresetから分けて投影する

同じKnowledge Packに人物と場所が含まれていても、すべてを同じ図へ出すとは限らない。`visibleEntityKinds`は関係図の表示対象を、`mapConnections`は根拠付きの地理接続を宣言する。UIが場所を都度除外したり、特定人物の地点を直接結んだりしない。

```text
Knowledge Pack（人物・場所・Assertion・Source）
  └─ LensPreset
       ├─ visibleEntityKinds → relationship projection
       └─ mapConnections     → map projection
```

MAP接続には2地点以上と、その接続を説明するAssertionを必須とする。ProjectionはSource・確度・レビュー状態を含めて返すため、線を選択した画面から「なぜそう言えるか」へ遡れる。

## 関係を混ぜない

同じ矢印に見える情報でも、意味の異なる関係は別Assertionにする。

- `genealogy`: 神話・系譜上の親子や出生
- `succession`: 皇位・役割・制度上の継承
- `route`: 史料記載または解釈モデル上の移動順序
- `identification`: 古代地名と現代地域の比定
- `textual-attestation`: どの史料に記載されるか
- `historical-context`: 成立環境、歴史的接触
- `influence`: 影響関係
- `syncretism`: 習合・再構成
- `classification`: 分析上の分類
- `conceptual-comparison`: 概念上の類似・差異
- `ritual`: 儀礼上の関係
- `enshrinement`: 神と祭祀地の関係
- `association`: 上記に還元しない関連

## 観点と競合仮説

Assertionは必ず一つ以上の`viewpointIds`を持つ。史料記述、学説、分析モデル、ユーザーの理解を区別する。

邪馬台国の所在地は一つに確定せず、九州説と畿内説を同じ`hypothesisGroupId: yamatai-location`へ入れる。LENSは両説を色分けして重ね、共通経路と分岐を表示する。

宗教関係は少なくとも次の三つのプリセットに分ける。

1. 歴史関係：成立環境、伝播、接触、影響
2. 習合関係：神仏習合、修験道などの併存・再構成
3. 概念比較：多神、唯一神、宇宙原理、自然、祖霊などの分析軸

概念比較は歴史的な派生関係を意味しない。たとえばユダヤ教、キリスト教、イスラム教は、単純な親子線ではなく、アブラハム系宗教への分類と個別の歴史関係を分けて扱う。

## 初期パック

`apps/web/src/domain/lens-packs/seed-packs.ts`に次のドラフトを保持する。

- `japanese-mythology`: 皇統神話の主経路、宗像三女神、周辺神、祭祀地、史料差
- `wajinden-routes`: 狗邪韓国から不弥国までの記述順、現代地名比定、九州説・畿内説
- `religion-relations`: 歴史関係、習合関係、概念比較

初期データは構造検証用である。宗像大社、宇佐神宮、文化庁・日本遺産、国立国会図書館の公的ページは該当節まで確認し、直接支持される祭祀地・地域関係と、九州説・畿内説が存在することだけを`reviewed`へ昇格した。神話本文の細かな系譜、各比定説の正しさ、解釈モデルは引き続き`draft`である。パック全体も`draft`のままとし、確認済みの線とレビュー待ちの線を混在状態のまま区別して表示する。

## 更新ライフサイクル

### Sourceの最小メタデータ

出典は別の複雑な管理基盤を先に作らず、Knowledge Pack内の`Source`として保持する。タイトルと種別を最小入力とし、確認が進んだ時点で著者、発行主体、公開日、URL、取得日、巻・章・ページ等の該当箇所、内容ハッシュを追記する。

`candidate`は調査候補または未確認、`reviewed`は該当箇所まで確認済み、`rejected`は採用しない参照を表す。Assertion自身の`reviewStatus`とは分け、資料を確認したことと、その資料から導いた関係を採用したことを同一視しない。

LENSでは全出典一覧を常時占有表示せず、選択中のEntityに接続するAssertionの出典だけを「この表示は何に基づく？」へ折りたたんで表示する。

### 表示時

LENSを開くたびにWeb検索しない。現在の`active`パックとユーザーのローカル探索記録から即座に投影する。

### 不足を見つけた時

1. Codex調査でReference Source候補とAssertion候補を作る。
2. Research Inboxへ保存する。
3. 原典・研究資料の該当箇所を確認する。
4. 採用したAssertionを`reviewed`へ変更する。
5. パックの新バージョンを作り、検証後に`active`へ昇格する。

### 更新規則

- 既存のパック版は上書きしない。
- ユーザーの探索記録を基礎知識で上書きしない。
- Web調査結果を直接`reviewed`へ入れない。
- 競合する学説は削除・統合せず、同じ仮説グループに並存させる。
- `active`版の更新時に、その版から作ったLensProjectionを無効化して再生成する。
- 重要な原典・研究更新がない限り、定期更新ではなく不足発見時の明示的更新を基本とする。

## 次の実装

`japanese-mythology`パックから宗像系譜を、`wajinden-routes`パックから倭人伝ルートと九州説・畿内説を投影し、MapLibre上の実地図と双方向に選択できる実装まで完了した。`religion-relations`パックは、歴史関係・習合関係・概念比較を混ぜずに切り替える関係図として実装した。次は原典・研究資料の該当箇所を追加し、ユーザーの訪問・関心を各LENSへ重ねる共通投影を整備する。
