# 次の訪問候補ポリシー

## 目的

次の訪問候補は、有名な場所や思い付きの場所を列挙する機能ではない。
ユーザーの未完了の関心と、訪問済み地点から構造化された知識の不足を、次の現地探索へ接続する。

このポリシーは個別の旅行記に依存せず、今後追加されるすべての旅行記へ共通に適用する。

## 候補の種類

候補は次の2種類に限定する。

1. `missed_visit`
   - ユーザーが行きたかった、次に行きたい、時間切れで行けなかったと明示した未訪問地。
2. `knowledge_unvisited`
   - 訪問済み地点から、LENSの知識関係と根拠をたどって導ける未訪問地。

再訪候補、追加調査、抽象的な地域名は、通常の「次の訪問候補」には含めない。
再訪は重大な見落としなど明確な理由がある場合だけ、将来の別機能として扱う。

## 採用ゲート

次の条件をすべて満たした場所だけを候補として採用する。

1. 未訪問であることを確認できる。
2. 実際に訪問できる具体的な地点である。
3. 次のいずれかの起点を持つ。
   - 旅行記またはユーザー発言による明示的な訪問意図。
   - 訪問済み地点から出典付きの知識関係で接続できること。
4. 現地で確認したい問い、比較対象、観察点のうち少なくとも1つを説明できる。
5. 単に有名、近い、同じ人物名が付くという理由だけではない。
6. 地点の実在、位置、訪問可能性を確認できる。
7. 事実、解釈、仮説、異説の区別を保持できる。

条件を満たさない思い付きの場所は `pending` とし、画面の候補には表示しない。

## 順位付け

採用ゲートを通過した候補だけを、次の観点で順位付けする。

1. 明示された行き残し・訪問意図。
2. 複数のLENSや過去の旅を橋渡しする度合い。
3. 現在選択中のLENSを直接拡張する度合い。
4. 既存の理解に対する比較、反証、異説検討への有用性。
5. 根拠の質と、訪問目的の具体性。
6. 既訪問地との重複の少なさ。

距離は品質の代用にしない。候補は近距離・中距離・遠距離に分け、各距離帯から意味のある候補を提示する。

## データの責務

訪問候補は個別のJourneyに閉じた付属物ではなく、Atlas共通のエンティティとして管理する。

候補は最低限、次を保持する。

- 地点ID、名称、位置。
- `missed_visit` または `knowledge_unvisited`。
- 候補の起点となるJourney、訪問済み地点、知識Connection。
- 訪問理由と、現地で確認したい問い・観察点。
- 根拠となる出典。
- 未訪問確認、レビュー、採用の状態。
- 不確実性と異説。

LENSの所属は候補へ手入力で重複保存せず、接続されたConnectionのfacetから導出する。
1つの候補が複数LENSに関係することを許容する。

## 旅行記取り込みとの関係

旅行記追加時は次の順で処理する。

1. 原文をローカルに保存する。旅行記本文はGitHubへアップロードしない。
2. ローカルLLMで訪問済み地点、明示的な行き残し、関心、主張候補をドラフト抽出する。
3. ユーザーが訪問状態と地点候補をレビューする。
4. 訪問済み地点と知識要素をAtlasへ反映する。
5. 既存LENSのConnectionを追加または更新する。
6. 明示的な行き残しを `missed_visit` として候補ゲートへ渡す。
7. 更新された知識グラフから `knowledge_unvisited` を生成し、同じ候補ゲートで検証する。
8. 採用された候補だけを地図とNEXT表示へ反映する。

単純な抽出と整形はローカルLLMで行い、候補採否のルール変更、データ設計、実装、検証はCodexで行う。

## 朝倉旅行記での検証

`朝倉.txt`は正式反映前のレビュー入力として扱う。

- 訪問済み地点をドラフト抽出し、地点と訪問状態を確認する。
- 吉野ヶ里遺跡は、原文に次回訪問の意図と比較したい問いがあるため、`missed_visit` の採用対象とする。
- 高良大社は、ユーザーが行きたかったと明示しているため、`missed_visit` の採用対象とする。
- その他の例示地点は自動採用せず、知識Connection、出典、現地での問いを満たすまで `pending` とする。
- 朝倉から生じるテーマは新しいトップレベルLENSを増やさず、既存LENSのサブテーマとして表現する。
  - 宗教: 式内社・地域祭祀。
  - 政治・社会: 地域秩序と国家祭祀への編入。
  - 地理・ルート: 朝倉・筑後川流域。

## UI原則

- NEXTには未訪問地だけを表示する。
- 「行きたかった場所」と「知識から見つかった場所」を見た目で区別する。
- 各候補に、どの訪問・Connection・LENSから導かれたかを表示する。
- 複数LENSにまたがる場合は、その重なりを表示する。
- 候補を選ぶと地図はその地点へフォーカスし、根拠と観察点を確認できる。
- 候補が増えても、旅行記ごとの色分けを候補の意味分類と混同しない。

## 完了条件

- 思い付きの地点が根拠なしにNEXTへ表示されない。
- 明示的な行き残しが知識推定より優先される。
- 同じ候補ルールを複数の旅行記へ適用できる。
- 候補の理由を訪問済み地点と知識Connectionまでたどれる。
- 旅行記本文をGitHubへ含めずに候補を再生成できる。
