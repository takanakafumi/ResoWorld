# ADR-0001: ローカルファーストのEvidence Graphから始める

- Status: Superseded in part by ADR-0004 (local-first remains an implementation option, not a product constraint)
- Date: 2026-08-30

## Context

ResoWorldの構想には、旅行記のAI解析、Knowledge Graph、3D Atlas、Time Slider、次の探索提案、将来的なWebサービス化が含まれる。

しかし、PoC段階で最も不確実なのは技術的な実装可能性ではない。個人の探索記録を構造化して接続したときに、根拠のある新しい見方と次の探索が本当に生まれるかである。

また、対象データには個人の訪問履歴、感想、宿泊情報、AIとの対話などが含まれる。初期段階から多人数向けクラウドサービスとして設計すると、認証、権限、データ隔離、同意、運用などが価値検証より先行する。

## Decision

PoCは、自分専用のローカルファーストな探索ツールとして開始する。

最初の中心UIは、根拠へ戻れる `Evidence Graph` とする。グラフ上のRelationはClaimから導出し、原文、情報の性質、時間、場所、生成元、レビュー状態を確認できるようにする。

初期データはローカルファイルとして保持し、公開Gitリポジトリには含めない。公開用には、必要に応じて匿名化したデモデータを別途作成する。

地図は小規模な2D表示から始め、3D AtlasはEvidence Graphの価値が確認された後に追加する。永続化はJSONから開始し、データモデルが固まった時点でPostgreSQL/PostGISへ移行する。

## Consequences

### Positive

- 個人データを公開せずに実データで検証できる
- 認証やマルチテナント設計より、コア体験の検証を優先できる
- AIの誤推論を人が確認する仕組みを早期に作れる
- Claimモデルを実データで修正してからDBスキーマを固定できる
- 3D表現への先行投資を避けられる

### Negative

- 初期PoCは、そのまま公開Webサービスとして展開できない
- JSONからDBへの移行作業が後で発生する
- ローカルファイルアクセスとWeb UIの境界を設計する必要がある
- 他ユーザーで価値が再現するかは別途検証が必要になる

## Revisit Conditions

次の条件を満たした段階で、クラウド化と多人数利用を再検討する。

1. 宗像・宇佐・国東シナリオでPoC成功条件を満たす
2. Claimモデルとレビュー操作が安定する
3. 匿名化デモデータで同じ体験を再現できる
4. 他ユーザーの探索記録でも試す価値があると判断できる
5. 外部AI送信、保存期間、削除、エクスポートに関する方針を定義できる
