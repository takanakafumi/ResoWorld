# ADR-0004: データ処理場所と送信範囲を選択可能にする

- Status: Accepted
- Date: 2026-08-31
- Supersedes: ADR-0001の「ローカル限定」を製品要件として読む部分

## Context

PoCは安全に実データを検証するためローカルファーストで開始した。しかしResoWorldの価値は、探索記録を統合し、学際的に分析し、周辺情報と接続する体験にある。旅行記やLENSデータをサーバーへ送らないことを固定要件にすると、クラウド同期、共同利用、高性能モデル、検索基盤、バックアップを不必要に制限する。

## Decision

ローカル処理は既定の実装選択肢として維持するが、製品要件として強制しない。保存場所、分析実行場所、外部処理へ渡す文脈範囲を独立して選択できる構造にする。

```text
storage: local | server | hybrid
analysis: local | server | hybrid
contextScope: minimum-brief | selected-records | full-dataset
```

旅行記、Evidence、訪問履歴、LENS、Derived Synthesisは、構成されたワークフローに応じてサーバーへ送信・保存できる。情報源、Assertion、レビュー状態などの由来情報は、処理場所にかかわらず維持する。

画面では現在のデータセットや処理プロバイダーを状態として表示し、`LOCAL ONLY`をResoWorld全体の能力として表示しない。

## Consequences

- 高性能なサーバーモデルへ十分な探索文脈を渡せる
- 複数端末同期、共有、サーバー検索を追加できる
- ローカル処理とオフライン利用も引き続き選択できる
- プロバイダーごとの認証、保存、削除、障害時の扱いを実装時に定義する必要がある
- 「送信しないこと」ではなく、現在どこで処理しているかを正しく表示する必要がある

## Non-goals

このADRは、現在のPoCが直ちに旅行記全文を外部サービスへ送信することを意味しない。送信経路を実装する際に、選択された範囲を正しく渡せるよう、ローカル限定をアーキテクチャ上の制約にしないことを決める。
